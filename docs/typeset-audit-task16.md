# Task #16 — 诗歌排版挑错 · 逆向归因与修复

## 结论一句话
线上 472 首诗里 **140 首（≈30%）** 的正文末行/分节处出现**非诗句内容**。根因是 `scripts/process-books.ts` 的诗体解析器**「无元数据/结构感知」——把每一行都当诗句**，且 `verify-data.ts` 只校验数量不校验排版。这不是单点 bug，是**工作流缺一道「排版/结构」门**。

数据链路：`books/*/source.md` → `scripts/process-books.ts` → `src/content/*/book.json` → `PoemView/TitleRenderer` → 部署

## 二、逆向归因（错误 → 工作流具体环节 + 根因）

### 根因 R1（R1，主因）：诗体解析器无「日期/元数据」识别 —— E1
源格式约定（`books/*/source.md`）：诗末为
```
<诗句...>
<空行>
1987年12月        ← 创作日期（元数据）
[p39]             ← 页码标记
```
`process-books.ts` 在 `[p39]` 处结束本诗（`currentPoem=null`），**但没有规则识别它上面的日期行**，于是日期被 `currentPoem.lines.push()` 收进正文。
→ **every** 带日期的诗（≈135 首）末行都渲染出日期。
（同一根因的两种源写法：weileaiqing 用裸 `1987年12月`；zhungaer 用 `**1972年5月**`——解析器只剥 `**` 不识别为元数据。）

### 根因 R2：解析器不识别「组诗分节标记」 —— E2/E3
组诗/长诗用两种分节写法：`#### N`（MD 四级标题）或裸 `N`（独立数字行）。解析器只跳过 ``` 栅栏（`trimmed.startsWith('```')`）和 `^　+` 副标题，**不跳过 `#### N` / 裸 `N`** → 分节标记当诗句泄漏。

### 根因 R3：无标点/字符归一 —— E4/E5
OCR/手工录入混入半角 `.` `(` 与中文同行；解析器只清 `**` 和 `>`，**不做全/半角标点归一** → 泄漏到正文。

### 根因 R4：校验层缺「排版门」 —— E1–E6 全部逃过
`scripts/verify-data.ts` 只验证：works.json 数量、book 章节数/诗数、essay 分隔。**不校验诗句内容形态**（末行是否日期、是否有裸数字/MD 残留/半角标点）。所以 140 首的排版错**一路绿灯到线上**。
（`.agents/skills/editorial-review` 有排版规范，但**是文档、无强制脚本门**，靠人自觉。）

### 根因 R5：源 schema 不统一 —— F1/放大以上
日期有 `YYYY年M月` / `**YYYY年M月**` / `**YYYY年M月D日 于X**` 三种写法；分节有 `#### N` / 裸 `N`；组诗编号连续性无校验（poem-1-22 缺 3/4/5）。**录入层无 schema 约束**，放大了 R1–R3。

## 三、最优修复方案（已定，不需 owner 决策）

按「**分层治本**」——不是逐处手改 140 首（治标、易复发），而是在**解析器 + 校验门**两层修，一次覆盖全部：

### 修复 1（治本，改 `process-books.ts`）：解析器加「元数据/结构感知」
- **日期行**：匹配 `^\*{0,2}(\d{4}年\d{1,2}月(\d{1,2}日)?(于\S+)?)\*{0,2}$` → 不入 `lines`，收进 `poem.composedDate`（渲染层单独处理，见修复 3）。
- **分节标记**：`^#{2,4}\s*\d+$` 或 `^\d{1,2}$`（独立行）→ 不入 `lines`，标记为 `poem.sections[]` 分节边界。
- **代码栅栏 ` ``` `**：已跳过，保留。
- **标点归一**：行首/句内半角 `.`→`。`、`(`→`（`、`)`→`）`、`,;:!?'`→对应全角（仅在与中文相邻时，避免误伤英文/数字）。

### 修复 2（治本，加校验门 `check_typeset.py`）：新增排版校验脚本，接进流程
对 `src/content/*/book.json` 逐诗扫描，**命中即 FAIL**（同 golden-rules 一并强制）：
- 末行形如日期 → FAIL（应进 composedDate）
- 正文含裸数字行 / `#+` 标题残留 / `**` / `>` 残留 → FAIL
- 行首半角 `.`/`(`、中英混排缺空格等 → FAIL
- 组诗分节号连续性自检（缺号预警）

### 修复 3（渲染层，改 `PoemView.tsx`）：日期/分节正确呈现
- `poem.composedDate` → 渲染在诗末**署名行**（小字、次级色，`1987年12月`），与正文区隔（符合 AGENTS.md「元数据用空间留白分层」）。
- `poem.sections` → 组诗分节用空行/分隔或 `#### N` 变成小节号，不再当诗句。

### 修复 4（数据，改 `source.md`）：修 E6 的 `1087年8月`→`1987年8月`（1 处）+ 复核 F1 缺节。

> 顺序：先改解析器（修复1）→ 重新 `process:books` → 跑新校验门（修复2）→ 改渲染（修复3）→ 构建自测 → 提交。**改 140 首源文件不需要**——解析器一处修全覆盖。

## 四、沉淀的可复用流程（后续直接套用）

### A. 「诗歌录入/修订」标准流程（新增步骤并入 website-update-sop）
```
1. 只改 books/<id>/source.md（GR-3 源唯一）
2. 源格式规范（录入必守）：
   - 创作日期：单独一行 `YYYY年M月` 或 `**YYYY年M月**`，置于诗末、[pN] 之前
   - 组诗分节：用 `#### N`（不混用裸数字），节内诗句用 ``` 包裹
   - 副标题：`　　　　xxx`（全角空格开头）
   - 页码：`[pN]` 单独一行
   - 中文标点用全角，禁止半角 . , ( ) ! ? 邻接中文
3. npm run process:books
4. node scripts/check_typeset.py      ← 新增：排版门（命中即 FAIL）
5. npm run test:data
6. npm run build
7. 构建后抽查诗句末行/分节（grep book.json 的 lines）
```
### B. `check_typeset.py` 校验清单（机械防呆，取代人工目检 140 处）
- [ ] 末行日期 → 应在 composedDate，不在 lines
- [ ] 无裸数字行（组诗分节号）
- [ ] 无 `#`/`**`/`>` 残留
- [ ] 无半角标点邻接中文 / 行首半角点
- [ ] 组诗分节号连续
### C. 归入 `.agents/skills/editorial-review`：把上述机械项从「文档建议」升级为「脚本必过」，配合 golden-rules（GR-2 版本心跳、GR-4 构建验证）形成闭环。
